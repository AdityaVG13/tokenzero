## Methodology

### Synthetic repo

A synthetic 1M-line repository is generated at runtime in a temporary directory
under `/tmp`:

| Parameter | Value |
|-----------|-------|
| Directories | 100 (`mod_0000` … `mod_0099`) |
| Files per directory | 10 |
| Total files | 1000 |
| Lines per file | 1000 |
| Bytes per line | ~50 |
| Total lines | 1 000 000 |
| Total size | ~50 MB |
| File format | `.rs` (Rust source) |
| Search needle | `BENCH_NEEDLE_FN` embedded at line 500 in 5% of files |

The repo is deterministic (Python `random.seed(42)`) so results are reproducible
across runs. It is removed on exit via a `trap` cleanup.

### Task suite

Five representative agent navigation tasks, each executed once:

| # | Task | TokenZero steps | Raw CLI baseline |
|---|------|-----------------|------------------|
| A | `read_50_lines` | `read --start-line 1 --end-line 50` | `head -n 50` |
| B | `grep_expand` | `find` (grep) + `expand` first blob ref | `grep -rn | head -20` |
| C | `tree_glob_read` | `tree --depth 2` + `glob '*.rs'` + `read` first match | `find -maxdepth 2` + `find -name` + `head -50` |
| D | `grep_expand_edit_verify` | `find` + `expand` + `edit` (rename needle) + `read` (verify) | `grep` + `sed -i` + `sed -n` |
| E | `recall` | `recall` (search recovery cache from prior tasks) | `grep -rn | head -10` (no cache equivalent) |

## Quality criteria

"No quality loss" means the following invariants hold:

1. **Byte-exact recovery** — every `expand` call recovers the exact bytes of
   the original content. TokenZero refs are content-addressed; the recovered
   bytes must match the source byte-for-byte. This is verified by the CLI's
   internal checksum validation on every `expand`.

2. **All tasks succeed** — each of the 5 navigation tasks completes with exit
   code 0. No task may fail silently; the script uses `set -euo pipefail` and
   checks the assertion at the end.

3. **No content loss** — TokenZero capsules hide raw content behind refs, but
   nothing is discarded. Every byte that is hidden from the visible context is
   recoverable via `expand`. The `raw_tokens` metric tracks the full content
   size; `visible_tokens` tracks only what the model sees.

4. **Edit integrity** — the multi-step edit (Task D) produces a valid file with
   the replacement applied. The read-back verification confirms the needle was
   renamed from `BENCH_NEEDLE_FN` to `RENAMED_FN` at the expected line.

5. **Budget compliance** — the total `visible_tokens` across all 5 tasks is
   strictly less than 32 000, proving the entire navigation workflow fits within
   a single 32 k context window.

## Integrity note (per tokenzero-bl6)

- **Single-run wall times** are subject to scheduler jitter. For publication,
  re-run with `RUNS` iterations and report medians. The primary assertion is
  about `visible_tokens`, which is deterministic and stable across runs.
- **`visible_tokens`** is TokenZero's tokenizer-accurate count of what the model
  sees, not a `bytes/4` proxy. It reflects the compact capsule output only.
- **`raw_tokens`** tracks the full uncompressed content size that was processed
  — the difference (`raw_tokens − visible_tokens`) is the compression achieved.
- **`output_bytes`** for raw CLI reflects unmodified stdout. Raw CLI has no
  compression or recovery layer, so its output size scales linearly with file
  size. This is the baseline TokenZero is compared against.
- The synthetic repo is generated fresh on each run and removed on exit. No
  modifications are made to the TokenZero repository itself.
- The benchmark does not depend on network access or external services. All
  operations are local filesystem + recovery cache.
- Re-run on the same host and same `tokenzero` version before publishing
  comparative claims. Do not compare numbers across different machines or
  TokenZero versions without recalibration.
